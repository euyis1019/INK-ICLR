# CM 实验版本、种子与配置对齐

核对日期：2026-09-16。本文区分已经测得的结果和后续执行规范；后者不追认为历史预注册，也不表示补跑已经完成。

## 先分清四件事

| 名称 | 实际含义 | 是否改变默认 CM |
|---|---|---|
| CM 的架构移植 | 把当前模型统计、逐层求解、留出选择、接受后重测的流程用于 T5 或 LLM；教师输出、可合并层和搜索粒度按架构适配 | 保留共同流程，但不能声称三个实现逐行等价 |
| FeatCal 移植 | `nlp/featcal_t5.py` 将 FeatCal 的特征校准流程用于本地 T5 专家及评测管线 | 是另一个方法的基线，不是 CM 的必选组件 |
| CM 目标特征插值 | 拟合目标同时参考当前学生与专家各自的层输入；插值强度为零时使用原始目标，非零时改变 CM 的拟合目标 | 是独立扩展，不能不标注就替代默认 CM |
| 多种子 | 固定方法和超参数，改变校准抽样，重复整个合并与评测过程 | 是重复协议，不是新方法，也不是挑选最高分种子的搜索 |

另有两种**串联顺序**：从 FeatCal 输出开始运行 CM，以及先运行 CM 再做 FeatCal。它们都不等于把目标插值机制放进 CM；各自单列。

“原型 / 正式”记录实现来源。工作台使用旧的搜索流程，正式 CLIP 使用显式拒绝候选及正式逐块选择流程。两者属于同一研究路线，但已有结果不能混成同一个重复实验。四个正式种子也不是“四种 CM”。

| 其它起点、正反串联 | 随所在列明确标注 | CLIP/T5 大多只有 seed 0；LLM 为 seed 42 | 初始化/组合表，不纳入多种子主结果 |

LLM 的 seed 42 有源码历史证据：提交 `43d4206` 添加 `--seed` 前，调用 `calib.texts` 不传 seed，该函数默认 42；补跑日志显式记录 1、2。它们与 lm-eval 的 Python、NumPy、Torch、few-shot 随机种子是不同字段。旧起点 CSV 曾把 LLM 误填为 seed 0，本次更正为 42，并保留推断依据。

当前论文没有 FeatCal 在 CLIP 九格或 LLM 上的完整实测表；不能把 T5 移植结果当作这些设定已有的基线结果。

## 参数名字相似，不表示控制同一件事

| 参数 | 控制什么 | 已用设置 |
|---|---|---|
| 初始化尺度 | CM 开始前的合并模型 | 默认 Iso-C 1.3；更换起点、尺度扫描另列 |
| CM 目标插值强度 | CM 拟合时参考多少专家自身的输入特征 | 默认 0；T5 扩展 0.3、0.6；0.15、0.45 只在 base seed 0 探索 |
| 更新幅度 | 当前模型向本轮候选权重走多远 | 每轮由留出教师 KL 选择，不按最终任务分数选 |
| FeatCal 自身参数 | 特征目标插值、锚点和求解正则 | T5 移植的插值 0.6、锚点参数 2.0、正则 0.00001；上游 Task Arithmetic 0.3 |
| 校准种子 | 选择哪些校准样本 | 不选最优 seed；按固定种子集合逐一报告 |

因此，CM 插值 0.6、FeatCal 插值 0.6、初始化尺度和本轮更新幅度不能合并成一个“alpha”。表格与配置文件使用不同字段。

## 对齐到什么程度了

1. **T5-base 原始 CM 与 FeatCal 已经有五个同编号种子。** 均值只差约 0.079 个百分点，CM 赢三个种子、FeatCal 赢两个。它们是默认完整流程的比较：CM 从 Iso-C 开始，FeatCal 从 Task Arithmetic 开始，不能据此隔离单个修正模块的效果。
2. **采统计样本已核对相同，全部数据预算尚不同。** 检查了 base 五种子和 large seed 0 的八任务缓存，共 48 组：两方法前 256 条的样本索引及 token 完全相同；CM 额外使用互不重叠的 256 条留出数据。FeatCal 默认流程不使用这份留出集。必须分开报告“统计 256”与“选择 256”，不能只写成两者都用 256 条数据。
3. **插值消融现在按共同种子 0、1、2 比较。** CM 原始目标为 84.8944、样本标准差 0.0427；插值 0.3 为 85.6385、0.0496；插值 0.6 为 85.7659、0.0809。三行的初始化、统计量样本数、留出数、四轮预算、CG 100 步和选轮规则一致。保留全部原始 5/4/3 次结果供追溯，但不把它们当作相同重复次数的受控比较。0.6 的任务分数更高，0.3 在已查 seed 0 的留出 KL 更低；不能依据任务分数事后改选主配置。
4. **T5 的串联不应再写成两份独立校准数据。** 已核对的两阶段都用 seed 0，FeatCal 的 256 条与 CM 采统计的 256 条相同。加上 CM 留出集，涉及 512 条不同样本；增加的是校准处理阶段与计算开销。旧文“两份独立校准数据”的措辞已修正。是否给其它方法同等选择预算仍需单独控制。
5. **CG 的起始权重也没有统一。** 正式 CLIP 和 T5 从当前权重开始 CG；工作台与 LLM 调用 `mats_bfm` 时未传内部初值选项，默认使用专家平均权重。这个“内层求解初值”与整次 CM 的 Iso-C 外部起点是两件事。有限 100 步不能保证不同初值等效；因此即使种子和轮数补齐，也不能把旧结果写成完全相同的求解协议。之前协议表把 LLM 写成“从当前权重开始”，本次更正。
6. **跨架构实现还有明示的适配。** 正式 CLIP 有全局及逐块搜索；T5 和 LLM 只有全局搜索。T5 使用教师答案上的 token 分布；LLM 使用 top-128 教师分布。LLM 的 TSV-M 起点曾用每段 4 层，其余通常每段 7 层，这是内存分块差异；不能把“相同四轮”扩写成全部实现设置逐项一致。选中轮数随 seed 不同是同一规则的结果，不是人为换超参。

缓存证据见 [calibration_cache_audit.json](data/calibration_cache_audit.json)。原始配置、实际结果和缺测状态见 [protocol_runs.csv](data/protocol_runs.csv)，包含本次找到的 110 条运行记录；代码与输入哈希在 [protocol_audit.json](data/protocol_audit.json)。该清单覆盖指定实验目录及已发表快照，不把缺少历史日志的运行标为配置已核验。

## 其余超参数实验也没有全设定覆盖

| 干预 | 已有记录 | 尚不能声称的覆盖 |
|---|---|---|
| 校准量 | CLIP B/32 八任务有 64、128、256；T5-base 有 128、256、512 | 基本是 seed 0；T5 的 128 运行同时将留出数改成 128，不能视为只改变统计样本量 |
| 轮数 | CLIP B/32 有 4、8、12；T5-base 有默认四轮、原版八轮、插值 0.3 六轮 | 没有所有骨干的配对多种子预算曲线 |
| 初始化尺度 | CLIP B/32 最多；T5-base 另有 2.0、3.0；工作台部分新规模格有 3.0 | 没有统一候选集合覆盖全部 settings，新增日志也不自动进入主表 |
| 收缩、搜索开关、冻结输出头、未归一化 | 在特定 CLIP/T5 设置上有独立消融 | 不能称为跨模型一致的组件结论 |
| 目标插值 | T5-base 最多，large 少量 | CLIP/LLM 主结果没有；跨架构目标插值还需要实现和实验，不能用现有结果填格 |

## 后续统一执行规范

这次把**共同重复集合定为 0、1、2、3、4**，适用于以后报告多种子的方法比较、目标消融和初始化对照。已有 seed 42 的 LLM 结果保留为历史补充，不改名为 seed 0。共同随机数的配对只在同一模型、任务与数据管线内成立，不表示不同模态的 seed 0 是同一份数据。

| 对齐项 | 统一要求 |
|---|---|
| 默认 CM | 目标插值关闭；Iso-C 起点尺度 1.3；每任务/域统计 256、独立留出 256；最多四轮；CG 最多 100 步并统一从当前权重开始；每轮重测；只按留出教师 KL 选步/轮。旧工作台和 LLM 要先修改求解初值，再重新执行，现有分数不能直接继承 |
| 同一 setting 的所有重复 | 同一个实现版本、模型/专家指纹、任务列表、样本 ID、tokenizer、数据 split、教师构造、参数精度、评测脚本及指标；只改预先列明的 seed |
| 跨 setting 的适配 | 教师形式、CLIP 分类头、T5 输出头、LLM top-128/截断长度/注意力后端及搜索粒度明确登记；同一 setting 内不得随方法或 seed 改动 |
| 目标插值消融 | 原始目标、0.3、0.6 用同一五种子集合；首先补齐 T5 base 和 large。仍标注为 T5 扩展，不声明 CLIP/LLM 已完成同一消融 |
| 样本量消融 | 单独改变统计样本数时，留出数保持 256；每个 seed 预先固定留出样本 ID，所有样本量的统计集合均与其互斥；已有不同留出预算的记录保留为旧探索 |
| 初始化对照 | 仅换起点，其余配置冻结。数据驱动起点须按同一 seed 构造；不能把一个 seed 0 的 FeatCal/RegMean 起点当作五个独立的上游重复 |
| 对手方法 | 保留原方法定义和推荐设置；同一数据池及评测协议，分别登记实际使用的数据量、选参机会和计算量。方法自带参数不强制取与 CM 同名参数相同的数值 |
| 公平比较层次 | 默认流程比较保留原推荐起点；相同起点的修正能力、相同总数据预算的比较另做受控表，不把前者称为后者 |
| 结果选择 | 提前登记候选集合、选择数据和准则；不以 GLUE validation 或其它最终评测分数选择插值系数、seed 或迭代轮；历史看过分数的探索不能追认预注册 |
| 汇报 | 同一表内使用同一配对种子集合，报告均值、样本标准差、每 seed 原始数与缺测；确定性无数据方法不复制五次来制造误差条 |

当前论文保留工作台九格作为同一历史实现的完整记录，正式四种子仍单列。后续严格统一时，工作台和 LLM 的 CG 初值要修改；相关五种子均需重新执行。也可将正式实现扩展为新的 CLIP 九格主线，同样需要整组执行，不能只替换 B/32 的一个格子。所有新结果完成前不改写旧记录的配置。

这里的“对齐”包含方法身份、数据与选择协议，不只是把种子个数写成五。还不能宣布所有实验已按新规范完成。

## 补齐清单与呈现

[alignment_plan.json](data/alignment_plan.json) 记录共同种子、配置与缺口，状态均为待执行，不是任务已入 GPU 队列。

- 先补 T5-base 插值 0.3 的 seed 4，以及插值 0.6 的 seed 3、4；large 的默认 CM、FeatCal 和两个插值配置补齐五种子，0.6 现有运行先确认 checkpoint 与完整评测。
- 若仅扩充旧协议，CLIP 工作台九格各缺 seed 1–4，正式 B/32 独立组缺 seed 4；严格统一 CG 初值后，工作台九格应重新做完整五种子，或者用正式实现整组重建。两个实现的重复数不能相加。
- LLM 旧协议中，Iso-C 有 seed 1、2 的 GSM8K，其它主要是 seed 42；统一 CG 初值后，十个起点都需要完整 seed 0–4，不能把旧 1、2 自动算作已完成新协议。RegMean 这类数据驱动起点也需核对并重建对应 seed。另补缺失的 coding、safety，以及 Gemma multilingual，才可汇报五域均值。
- 其它随机校准基线、换起点、串联与敏感性实验按相同规则逐组补齐；仍缺实现或协议信息的格子保留待核验，不拼入已完成比较。

论文正文继续放默认 CM；部分覆盖实验单列。插值表采用共同三种子作为当前可直接核对的消融，附录保留全部已有重复。FeatCal 的本地移植和论文自报分开标明，不挑其中有利的数字替换对手；当前 base 两方法接近、large 默认 CM 略低的事实均保留。
